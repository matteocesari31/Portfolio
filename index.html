Flatlist Product Thesis and Technical Architecture

Problem & Thesis

Apartment hunting is chaotic, relying on scattered tabs, screenshots, and group chats across portals with inconsistent formats. Flatlist isn't another rental portal; it’s a unified private catalog that starts the moment you save a listing. It captures fragmented listings, standardizes their details, and ranks them against your ideal apartment description. Built primarily for students and roommates, its adaptable data model supports global currencies and metrics.

How the Product Works

  1. One-Click Capture: A browser extension instantly extracts a listing's URL, text, and images directly from any existing portal.
  2. AI Enrichment: Background processes convert raw text into structured facts (price, layout) and inferred qualities (natural light, noise), retaining original excerpts as proof.
  3. The Dream Apartment Match: Users describe their ideal home in plain English. Flatlist scores every saved listing from 0–100 against this prompt and explains the rationale.
  4. Collaboration: Roommates can share catalogs, leave private notes, and compare match scores to make aligned decisions.

Core Engineering Principles

  • Raw Content is Canonical: Flatlist stores raw text and images. Structured metadata is a regenerable downstream projection, protecting against evolving portal layouts and AI prompts.
  • Speed First: Saving feels instant because AI enrichment happens asynchronously in the background.
  • Strict Security: Client access relies on Postgres Row-Level Security (RLS). Privileged background operations use Supabase service roles exclusively inside isolated edge functions.
  • Deterministic Filtering: Natural-language searches translate into explicit filter parameters against stored metadata, preventing AI hallucinations.

The Processing Pipeline

  1. Save: An edge function validates user limits, saves raw page content, and instantly returns a pending success status.
  2. Enrich: An asynchronous edge function calls OpenAI to extract facts and inferences, uses Nominatim for geocoding, and updates the status to done.
  3. Score: A comparison edge function evaluates the listing against the user's "dream apartment" prompt, logging a 0–100 score and rationale. Updating the prompt triggers a catalog-wide rescore.
